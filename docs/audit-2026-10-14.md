# TRX-AI audit — 14 October 2026

The audit covered the CLI and TUI entry points, inference transport and review stages,
fix generation and saving, guardrails, profiles and memory, graph integrations,
file watching, exports, evaluation, dependencies, and release packaging. Confirmed
problems below were fixed and regression-tested. This is a verification record,
not a guarantee that every possible input produces a correct model answer.

| Severity | Location | Confirmed problem and impact | Fix |
|---|---|---|---|
| High | `main.py`, `_build_fix_comment_header` | Newlines in a model-supplied explanation could insert executable statements into the saved header after fixed-code checks had run. | Flatten control characters and line breaks; neutralize closing comment delimiters. |
| High | `main.py`, `apply_code_fix` | A linked fixed-output file could overwrite the original or another file. Interrupted writes could leave partial output. | Reject linked destinations and replace output atomically through a temporary file. |
| High | `cli_input.py`, `history.py`, `guardrails.py`, `user_profiles.py`, `router_memory.py` | Recognized credentials could remain in prompt history, PDFs, profile preferences, or dictionary keys. | Redact these persistence boundaries; routing memory stores SHA-256 prompt fingerprints and reads legacy keys compatibly. Legacy history recall is redacted. |
| High | Runtime dependencies | Installed Pygments, Pillow, and urllib3 versions had known security advisories despite a newly resolved requirements environment being clean. | Patch the project and launcher environments and set security version floors in both dependency manifests. |
| Medium | `main.py:346` | The `status` command replaced the prompt state with a dictionary and crashed the next loop iteration. | Keep runtime status separate; exercise a complete real command sequence in integration tests. |
| Medium | `llm_client.py` | Valid JSON with the wrong shape could crash inference; null or container response fields could be accepted as text. | Validate the response object and accept only string content; malformed responses use normal retry/fallback behavior. |
| Medium | `guardrails.py`, `history.py` | Saving a session containing guardrail findings raised a JSON serialization error. | Convert dataclass findings to redacted JSON records. |
| Medium | `history.py:400` | Report filenames could escape the documented reports directory; nested report paths failed. | Resolve and enforce the reports boundary; create valid nested directories. |
| Medium | `history.py` | Long report cards/code overflowed pages, and comparison recommendations always claimed Run 2 improved. | Wrap text to measured width, paginate long sections, and derive recommendations from the actual comparison. |
| Medium | `watcher.py` | Non-Python fixed copies could trigger repeated auto-fixes; dependency directories were watched as source. Invalid UTF-8 could terminate handling. | Ignore all fixed-copy stems and dependency directories; handle decoding failures. |
| Medium | `graph_query_adapter.py`, `vector_memory.py` | Non-object cache JSON caused startup failures; concurrent graph-cache writers could corrupt persistence or mutate iteration. | Validate cache shapes and serialize graph-cache access with a lock. |
| Medium | `analyzer.py`, `cloud_memory_sync.py` | Cloud retrieval filtered by owner but not personality. | Apply both filters, matching local retrieval isolation. |
| Medium | `tui/engine.py`, `tui/app.py` | The TUI fix path accepted unsupported file types; the inspector could claim safety checks that had not run. | Share the code suffix allowlist and display only the checks actually available for the request. |
| Medium | `pyproject.toml`, `benchmarks/`, `.github/workflows/ci.yml` | Installed wheels omitted the benchmark dataset, so installed evaluation failed outside the checkout. | Package the dataset and add an installed-wheel CLI/dataset/TUI smoke check to CI. |
| Low | `config.py`, `personality.py`, `main.py` | Nonpositive cache/context limits, a missing personality file in a readonly directory, and command-prefix collisions caused avoidable failures. | Bound limits, keep builtin profiles available, and dispatch commands by exact command word. |
| Low | Launcher environment, `trx-ai.spec` | The launcher lacked prompt_toolkit; the legacy frozen-build specification omitted TUI CSS and benchmark data. | Install the declared launcher dependency and correct the specification's assets. |

Validation evidence:

- Final project-environment suite: **163 tests and 21 subtests passed**. Ruff and
  Git whitespace checks passed. Tests include malformed responses, persistence,
  export containment/redaction, concurrent cache writes, safe save annotations,
  linked outputs, and a complete classic command session.
- Real Qwen3 8B through the actual engine: chat passed in **17.06 seconds**;
  review and fix generation passed in **330.01 seconds**, including both Critic/Fixer
  revision passes and safety checks. The generated Python parsed, a fixed copy was
  saved, the original remained unchanged, and history/stats were recorded.
- The Python launcher was checked separately for model communication and TUI
  selection in an interactive terminal. Required runtime dependencies are present.
- Real filesystem modification delivered a watcher event. Offline smoke checks
  scored **10/10**. All **66** labelled cases completed through the offline fallback.
- Built-wheel installation outside the checkout passed CLI, dataset, and real
  headless TUI/CSS checks. CI now repeats this release check.
- Normal, comparison, and long PDF exports were extracted and rendered. Recognized
  secrets were masked, recommendations followed actual confidence changes, and
  text stayed within page bounds, including a 17-page stress report.
- Dependency audits of the resolved requirements, patched project runtime, and
  launcher runtime reported **no known vulnerabilities**. The project environment's
  `pip check` passed. Advisory details were checked against upstream
  [Pillow release notes](https://github.com/python-pillow/Pillow/blob/main/docs/releasenotes/12.3.0.rst),
  [urllib3's security advisory](https://github.com/urllib3/urllib3/security/advisories/GHSA-8988-9cw3-xx77),
  and [Pygments releases](https://github.com/pygments/pygments/releases).

Practical limits:

- The live test covers a chat prompt and one small Python repair, not all model
  behavior. The full review took about five and a half minutes on this machine.
- Offline benchmark completion verifies the fallback pipeline, not review quality:
  it detected **0%** of issue labels and **1.52%** of fix labels. Local-model review
  remains necessary for useful diagnosis. The full 66-case live-model quality
  benchmark was not run during this audit.
- Supabase and remote graph services were checked through mocks and fallback paths;
  no external production service was contacted. Optional embedding backends were
  checked for graceful fallback without downloading model weights.
- The legacy frozen executable specification was inspected and repaired; a native
  executable was not built. The supported Python and wheel paths were exercised.
- Secret and dangerous-call detection remain pattern-based. Python syntax checks
  do not prove semantic correctness; other languages have no compiler validation.
  Generated code was not executed during this audit.
- Local profiles isolate normal application context, not access by somebody using
  the same OS account. The shared system Python also contains unrelated package
  conflicts; TRX's isolated project environment has no dependency conflicts.

Local evidence is retained under the ignored `build/audit/` directory. User files
and the untracked logo were excluded from the commits.
